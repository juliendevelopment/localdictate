# LocalDictate v0.2.5 — insertion into web and custom fields

## Fix

- Automatic insertion into fields that accessibility shows as non-editable although the keyboard types into them (web fields, custom views in some chat apps). v0.2.4 refused them at start with « champ non éligible (modifiable=false … sélection=-1--1 …) ».
- In that case the text goes through the keyboard's editor, under stricter rules: same field and app at ✓, field text and cursor exactly as when the dictation started, nothing replaced, password fields excluded, insertion confirmed by reading the field back. Otherwise the text is copied and kept in the history as before.
- Fields that already worked (Keep, regular text fields) follow the same rules as before.

Checked by host tests only; insertion in the reported chat app is still to be confirmed on a phone.

## Installation

Installs over the previous version and keeps the models. See the v0.2.1 notes for a first installation.
